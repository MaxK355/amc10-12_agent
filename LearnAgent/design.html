1. Goals & Requirements

  • Assess: take a timed, AMC 10-style test; the agent scores it and diagnoses strengths and gaps.
  • Plan: generate a personalized one-month study plan from the diagnosis.
  • Teach: each study session has a concept explanation, worked example problems, and open Q&A.
  • Practice: the agent assigns topic-specific homework, reviews answers and reasoning, and logs errors.
  • Reassess & adapt: retest monthly, compare with earlier results, and adjust the plan; repeat continuously.
  • Reuse the platform: use the Copilot SDK agent loop, tool framework, and MCP; do not build a custom agent loop.
Scope: one learner (me), running locally on one machine. No multi-user accounts or hosting.

2. The Learning Cycle

Simulated test→ Score + diagnosis→ 1-month plan→ Lessons + Q&A→ Homework + feedback→ Weekly check-in→ Retest↻

Diagnosis: find causes, not just wrong answers

EvidenceDiagnosisRemedy
Cannot identify the relevant ideaConcept gapLesson + worked examples
Knows the idea, cannot find an approachStrategy gapGuided practice with hints
Correct setup, arithmetic slipExecution errorError log + careful-work drills
Solves it, but too slowlyFluency / timingTimed sets
Correct answer, weak reasoningUncertain masteryFollow-up questions

Monthly plan structure

  • Week 1: repair the highest-impact prerequisite gaps.
  • Week 2: problem-solving strategies on target topics.
  • Week 3: mixed topics and timed practice.
  • Week 4: consolidate, review the error log, then retest.

A 15-minute weekly check-in quiz can adjust the plan between monthly tests.

4. Learning Modes

Each activity runs in its own SDK session, with a mode-specific system prompt, tool set, and a compact learner summary. Mode rules are enforced by which tools are available, not only by prompts.

ModeAgent behaviorAnswer keys / solutions
AssessmentClarify instructions only; the UI handles answering. No chat about the math.Hidden
Test reviewExplain mistakes, ask follow-up questions, diagnose causesAvailable after submission
LessonExplain concepts, walk through worked examples, answer questionsAvailable for examples
Guided practiceProgressive hints (nudge → approach → key step)Revealed after an attempt
HomeworkLimited help; hints are recorded as "assisted"After submission
PlanningSummarize evidence, propose a monthly or weekly planNot needed

Scoring is never done by the model. The UI submits answers straight to the backend; code compares them with the stored answer (with SymPy for answer equality). The model only explains results and gives feedback on reasoning.

6. Data Strategy – Start with Public Data

Current state: no private data. Version 1 uses the public MATH dataset (Hendrycks et al., NeurIPS 2021) for both tests and homework.

MATH dataset

  • Source: huggingface.co/datasets/qwedsacf/competition_math · code: github.com/hendrycks/math (MIT license)
  • Size: 12,500 problems with full step-by-step solutions (7,500 train / 5,000 test), about 20 MB
  • Fields: problem, solution (LaTeX; final answer in \boxed{}), level (1–5), type (7 subjects)
  • Origin: AMC 10, AMC 12, AIME and similar contests. Personal study use only; do not redistribute.
  • Cost: $0

Known limitations of v1 data

  • No multiple-choice options: answers are typed as free responses. This is harder than AMC (no answer choices to use for elimination or checking).
  • Simulated difficulty: MATH levels approximate AMC difficulty; they are not calibrated AMC tests.
  • Diagrams: written as Asymptote code; v1 may skip diagram problems.

7. Simulated AMC 10 Test (v1)

  • Format: 25 problems, 75 minutes, drawn from the assessment pool.
  • Scoring (AMC-style): +6 correct, +1.5 blank, 0 wrong; maximum 150.
  • Captured: answer, skip, time per problem, optional confidence (1–3).
  • No help during the test; review starts after submission.

9. Guardrails

  • Math correctness: the agent checks computations with the math MCP server and prefers stored, verified solutions over new derivations.
  • Test integrity: during a test, the tutor has no access to answer keys or solutions.
  • Tool permissions: SDK built-in shell, file, and web tools are disabled; only learning tools are allowed (avoid approveAll).
  • Structured outputs: plans and homework are JSON proposals that code validates before saving.
  • Honest mastery: problems solved with hints count as "assisted", not mastered.
  • Content use: public data and my own books are for personal, local study only; nothing is redistributed. No automated scraping of AoPS (its robots.txt forbids ai-train; its Terms of Service limit use to "information purposes").
